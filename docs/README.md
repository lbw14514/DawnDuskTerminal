# 文档索引

本目录存放本模组的开发文档。

面向玩家的使用说明位于仓库根目录的 `README.md`。

## 阅读顺序

初次接手本项目时，先读 `architecture.md` 了解模块划分、关键类与注册流程。
再读 `development.md` 了解环境配置、构建、运行与测试流程。

其余文档依改动范围选取：

- 仅调整地形、结构生成与特征移植时，阅读 `worldgen.md`。
- 仅更换群系或调整地表方块时，阅读 `biomes.md`。
- 仅修改传送门判定与流体反应时，阅读 `portal.md`。
- 仅调整合成配方与标签时，阅读 `crafting.md`。
- 仅调整数值参数时，阅读 `configuration.md`。
- 需要查阅模组的世界观与设计设定时，阅读 `设定.md`。

## 书写规范

文档正文一句一行，不要把一个整段写成一行。这样 diff 以句子为单位，一行只对应一个意思，审阅时不必横向滚动。

- 一句一行：句子写完即换行。
- 每行不超过 120 列，与 `build.gradle` 里 palantir 的 `ColumnLimit` 一致。
  列宽按显示宽度算：中文与全角标点计 2 列，ASCII 计 1 列，所以一行大约只放得下 50~60 个汉字。
- 一行超宽时先改写：把拖着十几个分句的长句拆成几句，或拆成列表、表格，而不是在逗号处硬断。
- 改写以可读为先，不必与原文逐字一致，但类名、ID、数值与行为描述不得变。
- 段落之间空一行；列表项的续行按内容列对齐。
- 表格行不能换行：单元格只写结论，说明文字挪到表下的要点里。
- 代码块与命令行同样不强制换行。
- 换行只影响源码阅读，不影响渲染：Markdown 的单个换行在段落内会被合成为空格。

这几条没有对应的自动格式化工具：Prettier 与 mdformat 只按空格断行，对中文无效，而硬断句本身也不解决问题。

## 文件

- `architecture.md`：模块职责、关键类、注册流程、事件、网络、Mixin 与已知遗留问题。
- `worldgen.md`：维度类型、噪声设置、调色板群系源、地表规则、特征移植与结构白名单。
- `biomes.md`：占位群系对照、每个原版气候格子的占用者、方块命名对照，以及尚未落地的名称。
- `portal.md`：传送门判定、触发、即时传送、落点门、稳定效果，以及流体与桶的处理。
- `crafting.md`：苍穹石顶替石头与圆石、标签布局、原版配方改写、NeoForge 覆盖机制中的风险点与测试。
- `development.md`：环境、构建、运行、游戏测试、指令、CI、移植脚本与常见问题。
- `configuration.md`：全部配置项、默认值与作用。
- `设定.md`：模组的世界观与内容设定，可作为内容设计的依据。

## 相关文件

- 仓库根目录的 `AGENTS.md`：面向 AI 与协作者的最短上手路径。

- `docs/ysm.md`：Bedrock / YSM 动画运行时，模型包布局与新增模型的步骤。
