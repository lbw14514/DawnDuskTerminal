# DawnDuskTerminal 晨昏线维度

本项目是一个 Minecraft 1.21.1 NeoForge 模组，用于添加名为「晨昏线」的维度。该维度内没有昼夜更替，太阳高度由玩家坐标决定，世界则被一条晨昏线划分为昼侧与夜侧。

> **本项目处于早期开发阶段**
>
> - 版本号 `0.1.8` 尚未发布正式版。
> - 功能与数据结构仍在变动，存档随时可能出现不兼容。
> - 尚未进行完整测试，因此崩溃与地形异常均属正常现象。
> - **硬依赖暮色森林与 GeckoLib**；若未安装这两者，加载器将在启动阶段直接拒绝加载。
> - 请勿用于正式存档，并请您自行准备备份。

# 第一部分 普通使用者

## 使用前必读

**模组硬依赖暮色森林**，且需使用对应 1.21.1 分支的版本；若缺少该模组，加载器将报告缺失依赖。

**模组硬依赖 GeckoLib 4.9.3 以上**；高塔恶魂的模型与动画由它驱动，缺少时同样会报告缺失依赖。

**维度内没有昼夜**，时间锁定在黄昏，因此睡觉仅能重置重生点。

**太阳高度随坐标变化**：向昼侧移动时太阳升高，向夜侧移动时太阳降低。在同一服务器内，若两名玩家的位置不同，则各自观测到的太阳高度也不同。

**水即传送门**：这个维度的水是传送门流体，接触即触发传送，因此不应在海洋中游泳。

**开启条件**：须先在暮色森林中击败九头蛇、暮色恶魂与冰雪女王三者之一。

## 逐功能说明

### 进入维度

须先击败暮色森林三个 boss 之一，然后按下方建造判定摆放传送门。

### 建造判定

| 条件 | 要求 |
|---|---|
| 水池 | 4 格以上、8 乘 8 以下，且为水平连续水源。 |
| 四周 | 可种植方块 |
| 上方 | 任意植物 |
| 投料 | 三种战利品之一 |
| 触发 | 满足条件的主动动作 |

### 回程

落点固定，不会陷入山体内部。进入维度时会在落点旁生成到达门；若搜索超过时间预算，则直接铺设回退平台。

### 杂项

接触传送门流体将受到减益效果，具体效果待定。

试验物品 114 既能食用也能放置；食用一个等于食用 8 个暮色森林的试验物品 115，食用后会随机播放一次恶魂受伤音效。

放置后的 114 与暮色森林的试验物品 115 方块行为一致，共 8 片：以空手右键可食用其中一片；手持 114 点击该方块一次即可补满；只有在潜行状态下持物点击已补满的方块，才能将其收走；方块处于满状态时，可用红石粉点击成带红石的那一版。

带红石的那一版不补充片数，每收到一次红石信号即随机播放一次恶魂受伤音效，消耗其中任意一片时同样会播放一次。

### 装备与武器

装备按材料分为六套，每套包含五件工具与四件护甲。

| 等级 | 材料 | 数值 | 获取 |
|---|---|---|---|
| T1 前（≤铁级） | 天门松原木 | 工具与护甲均对标铁级。 | 容易 |
| T1（钻石级） | 苍穹锭、砷铅铁锭 | 工具与护甲均对标钻石级。 | 进入维度后 |
| T2（高于钻石） | 绯色钼锭、狄拉克锭 | 四件合计 25 护甲、14 韧性；工具 2031 耐久、9 速。 | 需要先击败本模组 boss，狄拉克除外 |
| T3（终局级） | 䤧锭 | 四件合计 30 护甲、20 韧性；工具 2600 耐久、10 速。 | 待实装 |

T2 的绯色钼护甲四件穿齐后持续提供生命恢复；狄拉克与 䤧 没有套装效果。狄拉克属于可绕开进度门槛的材料，分布区域稀有，无须击败 boss。

工具挖掘等级在 T2 与 T3 中都属于下界合金那一档，原版没有更高的标签，两档的差别在于耐久、速度、攻击加成与附魔值。

砷铅铁钼反应权杖在以右键使用时发射一颗砷铅铁球，每发消耗 1 个；命中后留下 75 tick 的反应场，范围是半径 4、高 ±1.5 的圆柱，每 20 tick 结算一次伤害。该权杖可附力量、火矢、冲击、多重、穿透与快速装填，数值照搬源 mod。

生砷铅恶魂肉沿用腐肉的机制，有概率给予饥饿效果；熟肉是普通食物。

皮革与肉由高塔恶魂掉落。

装备贴图目前是原版铁与钻石贴图加色阶的占位图，详见 `docs/development.md` 的贴图一节。

## 以苍穹石替代石头

维度里没有原版石头与圆石，因此苍穹石同时算作这两者。

凡以石头或圆石为材料的配方均可使用苍穹石代替。

- 石头系：石头、石头砖、石台阶、石楼梯、石按钮、石压力板、中继器、比较器与平滑石头。
- 圆石系：圆石台阶、圆石楼梯、圆石墙、苔石、闪长岩、安山岩、发射器、投掷器、观察者、活塞、拉杆与盔甲纹饰模板。
- 站台方块：熔炉、酿造台与石切机。
- 石制工具：共五件。

产物一律是原版方块，苍穹石只顶替原料位。

在熔炉中，它既可烧制出原版石头，也可烧制出平滑石头。

## 流体反应

| 接触组合 | 产物 |
|---|---|
| 传送门流体与水 | 易碎的苍穹 |
| 传送门流体与岩浆 | 混乱石 |
| 传送门流体与热情的暮光 | 苍穹石 |
| 热情的暮光与水 | 暮色森林的极光方块 |
| 热情的暮光与岩浆 | 炽热的方块 |

> **注意**：维度内已经没有原版水与岩浆，因此只有从外部带进去的流体才会触发前两组与后两组反应。
> 维度内部自然发生的是「传送门流体与热情的暮光」这一组。

## 常见问题

**Q：进入维度后无法返回**
往回走进水里，或使用传送指令。

**Q：太阳不移动**
太阳随坐标变化，不随时间变化；玩家自身不动时，太阳也不移动。

**Q：环境为何如此昏暗**
因为玩家处于夜侧，向昼侧移动后会变亮。

**Q：安装光影后天空显示异常**
光影会覆盖本模组自绘的天空，因此不保证兼容。

**Q：在海洋中移动即触发传送**
此现象为刻意设计，水体即传送门，因此在设计上无法在海洋中正常游泳。

**Q：多人游戏中其他玩家看到的天空不同**
这是正常现象，每位玩家按自身的坐标计算。

**Q：在海洋中移动即触发传送**
此现象为刻意设计，维度里的水就是传送门流体；站在水里达到 2 个以上相邻液体时，即会被判定为传送门。

**Q：热情的暮光为何无法燃烧**
此行为为刻意设计，它只复用岩浆的方块属性，烧实体、点火、岩浆粒子与清除植被均已被去除。

**Q：地形与主世界完全一致**
地形管线确实移植自原版主世界，但噪声参数注册在本模组命名空间，噪声场由世界种子重新派生，因此它是同坐标下的另一套地形。

**Q：地形出现空洞或穿模**
地形已换回原版主世界管线；若仍存在异常，请您提交截图与坐标。

| 机制 | 判定方式 |
|---|---|
| 无昼夜 | 由 `dimension_type` 锁定 `fixed_time`。 |

## 完整对照表

### 群系

维度不自带群系，直接使用原版主世界的 55 个群系，由 `minecraft:multi_noise` 的主世界预设按气候参数分布。

### 按高度群系

该机制已移除，维度只有一条连续地表，不再按高度强制群系。

## 地形生成要点

### 移植自原版主世界

`worldgen/` 下的地形层是原版主世界地形管线的整体移植，由脚本生成，请勿手动修改。

| 目录 | 内容 |
|---|---|
| `worldgen/noise/` | 噪声参数，与主世界同名同参数。 |
| `worldgen/density_function/` | 密度函数，主世界噪声路由器整套搬入。 |
| `worldgen/noise_settings/chrono.json` | 主世界 `noise_settings/overworld.json` 的移植。 |

生成脚本 `tools/port_overworld_worldgen.py` 从 Gradle 缓存中的 Minecraft 客户端 jar 提取原版数据，把引用重新指向本命名空间，并校验每条引用都能解析。

```
python tools/port_overworld_worldgen.py          # 重新移植并校验
python tools/port_overworld_worldgen.py --check  # 只校验
```

### 种子派生

引擎为噪声场播种的方式如下。

```
NormalNoise.create(randomFactory.fromHashOf(噪声键的资源位置), 参数)
randomFactory = 噪声设置.随机源.newInstance(世界种子).forkPositional()
```

噪声场因此是世界种子与噪声键资源位置的纯函数。

把同一份参数注册到 `dawnduskterminal:` 命名空间，噪声场就随之改变，维度地形于是有主世界的质感，却是从世界种子派生出来的另一套地形，而不是同坐标的主世界复制品。

### 移植边界

下列部分不经过数据包，仍然是原版那一份。

| 部分 | 原因 |
|---|---|
| `old_blended_noise` 基础三维噪声 | 引擎硬编码用 `minecraft:terrain` 播种。 |
| 含水层与矿脉的位置随机 | 硬编码 `minecraft:aquifer` 与 `minecraft:ore`。 |
| `minecraft:zero` `minecraft:y` `minecraft:blend_*` | 代码注册的单例，本身不含噪声。 |

### 方块替换

维度自己生成模组方块，没有「生成完再改」这一步。

| 来源 | 交给谁 |
|---|---|
| 地形主体 | `noise_settings/chrono.json` 的 `default_block` = `canopy_stone` |
| 含水层与海洋 | 同文件的 `default_fluid` = `portal_fluid` |
| 地表规则 | 同文件 `surface_rule` 里每个 `result_state` |
| 群系特征铺出的（花岗岩、闪长岩、安山岩、凝灰岩、岩浆、雪、浮冰、沙洲、湖底石壳、绯红钼矿） | 维度自带的群系副本，其 `features` 指向自带特征副本 |
| `y < -54` 的岩浆层 | 一处 mixin，引擎把这一层硬编码在代码里 |

维度自带的副本与 `minecraft:*` 一一同名，只把要铺设的方块替换为模组方块。

| 内容 | 数量 |
|---|---|
| 群系副本 | 53 |
| 配置特征副本 | 52 |
| 放置特征副本 | 151 |
| 原版群系标签合并 | 50 |

原版气候表（climate 到 biome）只在代码里生成，无法通过数据包写出，因此 `dimension/chrono.json` 使用 `dawnduskterminal:palette` 群系源，委托原版 `multi_noise` 预设，再按同名替换为副本。

> **群系 id 会变**：F3 与 `locate biome` 显示 `dawnduskterminal:plains` 而不是 `minecraft:plains`。
> 原版群系连同其标签原样保留，主世界不受影响。
>
> **那 50 个标签合并是必须的**：结构生成与刷怪门控都依赖于原版群系标签。
> 若未把副本加入其中，白名单内的结构也将找不到落点，刷怪规则同样不正确。

整条链路由 `tools/port_overworld_worldgen.py` 生成，重新运行即重新移植并逐项校验。

### 关键参数

以下参数取自该维度的噪声设置文件 `noise_settings/chrono.json`，除另行注明者外沿用主世界的取值。

| 参数 | 值 |
|---|---|
| `sea_level` | 63 |
| `default_block` | `dawnduskterminal:canopy_stone` |
| `default_fluid` | `dawnduskterminal:portal_fluid` |
| `aquifers_enabled` | true |
| `ore_veins_enabled` | true |
| `surface_rule` | 主世界那一套，按群系铺草、泥土、沙、沙岩、深板岩 |

> **注意**：该维度的 `default_fluid` 为 `dawnduskterminal:portal_fluid`，所以自然生成的水体本身即为传送门流体，接触即触发传送。建造传送门时所用的水池则以 `minecraft:water` 摆放，待判定成立并投入投料物之后，再由 `portal/PortalBuilder` 转换为传送门流体。

## 逆向结论

| 结论 | 影响 |
|---|---|
| 上游传送门建造判定是水、可种植方块、植物与投料 | 直接照抄判定顺序。 |
| 上游群系按自己的地形高度铺特征 | 搬到空岛会悬空，需要高度修正或自建群系。 |
| 天光烘焙进区块 | 修改天光后旧存档需要重新计算。 |
| 天空色按玩家所在群系插值 | 若需精确渐变，只能自绘天空。 |

## 从源码构建

构建期从 maven 自动拉取暮色森林（CurseMaven）与 GeckoLib，因此需要联网，且不再需要往 `libs/` 放置 jar。

```
./gradlew build
```

产物在 `build/libs/`。

开发期运行命令如下。

```
./gradlew runClient
./gradlew runServer
```

> 首次构建会下载并反编译 Minecraft 约 1 到 2 分钟，首次 `runServer` 还会额外下载约 770MB 资源。

## 关键映射

| 目标 | 手段 |
|---|---|
| 锁时间 | `dimension_type.fixed_time` |
| 允许睡觉 | `dimension_type.bed_works` |
| 坐标 1 比 1 | `dimension_type.coordinate_scale` |
| 主世界地形 | 移植 `noise_settings/overworld.json` 与整套密度函数 |
| 与主世界地形区分 | 噪声参数改注册到本命名空间，由世界种子派生 |
| 群系 | `minecraft:multi_noise` 主世界预设 |
| 维度方块（地形与地表） | 直接写进 `noise_settings/chrono.json` 的 `default_block` `default_fluid` `surface_rule` |
| 维度方块（特征铺出的） | 维度自带的群系副本 + 特征副本 |
| 群系 | 委托原版 `multi_noise` 预设，再按同名替换为自带副本（`dawnduskterminal:palette` 群系源） |
| 群系标签 | 生成 50 个原版群系标签合并，并把副本加入其中 |
| `y < -54` 的岩浆层 | 一处 mixin，引擎把这一层硬编码在代码里 |
| 方块属性 | 模组方块用 `BlockBehaviour.Properties.ofFullCopy(原版方块)` 复用属性 |
| 传送门建造 | 沿用上游的建造判定思路 |
| 击杀门槛 | 由玩家附件记录进度 |
| 掉落投料 | 战利品表修改器 |
